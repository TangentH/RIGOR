# Paper baselines

## DA3-Legacy

`configs/da3_legacy.yaml` is the frozen scientific preset used for the
DA3-Legacy results. It keeps the same four-view DA3 front end, chunking,
sampling, confidence masks, and point-cloud cleanup as RIGOR while using the
predecessor single-image retrieval and graph policy. Run-local input and mask
paths are supplied by the workflow runner; they are intentionally absent from
the preset.

Pass `--workflow-config tools/hilti_workflow/configs/da3_legacy.yaml` to the
standard single-run or batch workflow. Use a separate output root for each
system.

## DA3-Sequential

The paper's DA3-Sequential comparator is materialized from the *same frozen
backbone predictions* as RIGOR, before loop closure and before virtual-rig
repair:

```bash
python tools/hilti_workflow/materialize_da3_sequential.py \
  --cache-root /path/to/rigor-work-root \
  --output-root /path/to/baselines \
  --repo-revision <release-commit> \
  --run floor_6/2025-06-18/run_1 \
  --materialize
```

Omit `--materialize` for a read-only admissibility check. The input root must
contain the matched RIGOR run's unmodified
`_work/_da3_work/_tmp_results_unaligned/chunk_*.npy` files and an admissible
pre-loop pose artifact. The default sampling seed is 2027.

This cache-based construction controls for the backbone predictions. It is
not a claim that an arbitrary loop-disabled workflow run is bit-exact: exact
rematerialization requires the unrepaired raw chunk cache from the matched
RIGOR run. If that cache is unavailable, rerun the matched RIGOR trunk first.
Use only trusted prediction caches generated by the reconstruction workflow.
